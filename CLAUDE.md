## Project Overview

Bare-metal Rust firmware for the **Texas Instruments MSP430FR5969** microcontroller dev board. No RTOS, no `std` — this is `#![no_std]` / `#![no_main]` embedded development.

## Build Commands

```bash
# Build (requires nightly toolchain for build-std)
cargo +nightly build

# Flash and run via mspdebug
cargo +nightly run

# Check without building
cargo +nightly check
```

Requires the **nightly** Rust toolchain (for `-Z build-std=core` on the `msp430-none-elf` target). The TI MSP430 GCC toolchain must be installed — the linker path is hardcoded in `.cargo/config.toml`.

## Architecture

**Workspace layout:**
- `dave_ti/` — Application crate. Entry point is `_start()` in `src/main.rs`. Contains the linker script (`memory.x`) defining MSP430FR5969 memory regions (2KB SRAM, 48KB FRAM).
- `pac/` — Peripheral Access Crate auto-generated by `svd2rust` from `msp430fr5969.svd`. Provides typed register access for all MSP430FR5969 peripherals. This is a ~71K-line generated file — do not manually edit `pac/src/lib.rs`.

**Key configuration:**
- `.cargo/config.toml` — Sets `msp430-none-elf` target, enables `build-std = ["core"]`, configures TI GCC linker and `mspdebug tilib` as the runner.
- `dave_ti/memory.x` — Linker script with memory map: RAM at 0x1C00 (2KB), FRAM at 0x4400 (48KB), interrupt vectors at 0xFF80, reset vector at 0xFFFE.

**Runtime model:** No runtime startup code — `_start` is the direct reset vector entry point. The watchdog timer must be disabled first. A custom `#[panic_handler]` loops forever.
